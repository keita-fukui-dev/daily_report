## わかったこと
- Context APIは「周りの環境を作って読み取るためのReactの窓口」。Props Drillingの対策になる
- APIは本来「機能を使うための窓口」。document.getElementByIdやuseStateもAPIにあたる
- Cursor のコード画面上で気になる箇所をCommand+クリックすることでpropsの定義元へジャンプでき、コードトレースが速くなる
- DevToolsのComponentsタブで親子関係とpropsの実体（関数propsの親側の関数名）を一発確認できる
- さらに便利な関数名の追跡方法があり、コードエディタ上で孫コンポーネントの関数propsを選択した上でCommand+Shift+Fで全体検索すると子と親のpropsが一覧で分かる
- GitHub Pagesはビルドでコンポーネント名が短縮される。トレースはnpm run devで立ち上げたWebブラウザ上で行うべし
- 条件付きレンダリングのコンポーネントは、操作して表示させないとComponentsタブに出ない
- プロパティショートハンドは、キーと変数名が同じ時に、例えば「text: text」を「text」と省略する記法
- formタグはブロック要素だが、CSSのflexで横並びにできる。インラインかブロックかの判別は重要
- Props Drillingの検討順は、children → Context API → 状態管理の順
- useEffectは非同期処理や副作用に関わり、ローカルストレージ保存などに使える。依存配列は監視する値を入れる
