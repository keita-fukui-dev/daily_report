## 取り組んだ課題一覧
- React 8日目：メッセージアプリのコードトレース（続き）
  - メッセージ入力から送信完了までの流れを、全体把握後に詳細まで追跡

## わかったこと
- ハンドラー命名のパターンを自分の中で固定すると、認知負荷が大きく下がる
- [ ] (ブラケット) には、配列だけでなく、オブジェクトのプロパティ参照やキーの変数指定もある。
- アロー関数でオブジェクトを即時返却する場合、`({ ... })` のようにパーレンで囲む
  - 囲まないと `{}` がブロックと解釈され、エラーになる
- トレース手順は次の流れで進める
  - data.js 等でデータの形を確認する
  - App.jsx の state とハンドラーを常に表示しておく
  - 親から順にコンポーネントを読み、全体像を掴む
  - `npm run dev` で起動し、DevTools とエディタで1つの操作を最初から最後まで追う

## 感じたこと
- トレースに不慣れで、「どこを見ればいいか」を探す時間が長かった
  - Command + Shift + F でもDevTools の Components タブでも目的の箇所が中々見つからないことがあった
- keyにIDを持ち、valueにobjectのlistを持つobjectで、使用されているブラケットが配列かobjectのプロパティ参照か混同し詰まった
- 子コンポーネントの state やハンドラーも確認が必要で、手間がかかった
- 変数を行ったり来たりして追い、時間を浪費した感がある
- 全体の流れを瞬時に把握できるレベルになりたい。
