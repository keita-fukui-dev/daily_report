## わかったこと
- ディレクトリ構成は utils、types、data、components の4分割の責務分離で問題なし。純粋関数の utils を分離した点も良い構成
- map の key にアイテム名だけを使うと、同名入力で重複エラーになるリスクがある。インデックスとアイテム名の複合キーにして一意性を担保した
- CSS のカスタムプロパティを定義したら、色指定は全箇所でそれを使い統一する
• Next.js が生まれた背景：HTML と JS のファイルを行き来する不便さを React（JSX）が解消した。一方、React と TypeScript だけの CSR はサーバー側での事前レンダリングが行われないため、初期表示速度の面で SEO に不利になる
- Next.js はSSR（サーバーサイドレンダリング）や SSG（スタティックサイトジェネレーション）といったレンダリング戦略を選べる。サーバーコンポーネントとクライアントコンポーネントも使い分けられる
