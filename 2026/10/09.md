## わかったこと
- コンポーネントの構造と状態管理
  - 親の上に更に上位の親を作り、state を一括で保持する形にリファクタリングした
  - タイムトラベル機能の実装で、配列の配列の形で履歴を管理した
  - 何でも state にせず、state なしで管理できるものは削る。バグが減り、コードも理解しやすくなる
- key は React 専用の特殊なプロパティで、`props.key` では受け取れない（参照するとエラーになる）
- `map` 使用時は、タグがネストしていても一番外側（`map` 直後）のタグに key を指定する。指定しないと React が要素を識別できない
- key は DB の ID などユニークな値が基本。追加・削除・並べ替えが絶対に起きない場合に限り、インデックスでもよい
- イミュータビリティ（不変性）の重要性を、昨日に続き再確認した（Reactに認識させるため）
- コンポーネント名は大文字から始める。JSX 内で HTML タグと区別するためである
- `useState` の引数は初期値で、初回レンダリング時のみ使われる。以降は現在の値と更新関数（`setSomething`）が使われる
